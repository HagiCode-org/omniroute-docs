# CLI 설정 미리보기 및 쓰기

인증이 필요한 `/api/cli-tools/config` 및 `/api/cli-tools/apply` 경로는 캐시할 수 없고 민감 정보가 마스킹된 미리보기를 반환합니다. 기존 인증 및 인가 검사는 그대로 유지됩니다. 요청 본문은 알 수 없는 필드를 거부합니다. 명시적인 base URL은 사용자 이름/비밀번호 자격 증명이 포함되지 않은 HTTP(S)여야 하며, 생략하면 서버에 설정된 base URL이 사용됩니다.

일괄 미리보기의 경우 `GET /api/cli-tools/config`는 선택적 `baseUrl` 쿼리 매개변수를 받으며, 설정 자격 증명은 `x-omniroute-config-api-key` 헤더에서 가져옵니다. 쿼리 문자열에 포함된 자격 증명은 거부됩니다. `POST /api/cli-tools/config`는 JSON 본문에서 `toolId`, `baseUrl`, `apiKey` 및 선택적 `model`을 받습니다. 응답은 성공 경로와 오류 경로 모두에서 `Cache-Control: no-store`를 사용합니다. 미리보기 텍스트는 자격 증명을 담은 사용 가능한 설정이 아닙니다.

미리보기 프로젝션은 직렬화된 호출자 자격 증명과, 병합된 JSONC, TOML 또는 YAML profile에 이미 존재하는 자격 증명 필드를 마스킹합니다. apply 경로는 원본 설정을 기록하며, 미리보기 마스킹은 디스크에 있는 값을 변경하지 않습니다. 잘못된 형식의 JSON은 400으로 거부됩니다. 공개 오류 응답은 표준 정제 오류 응답 구조를 사용합니다.

설정 적용은 대상 디렉터리 안의 비공개 임시 파일을 사용하며, 이를 플러시한 뒤 원자적으로 이름을 바꿔 제자리에 놓습니다. 파일과 백업은 `0600` 모드를 사용하며, 권한은 이름 변경 전에 소유한 디스크립터에 설정됩니다. 최종 대상이 심볼릭 링크이거나 일반 파일이 아닌 경우는 거부됩니다. Codex와 OpenCode의 읽기 또한 기존 TOML/JSONC를 병합하기 전에 최종 경로의 심볼릭 링크를 거부합니다. 이것이 상위 디렉터리를 제어하는 공격자에 대한 보호를 보장한다는 의미는 아닙니다.

컨테이너 쓰기 가드는 계속 활성 상태입니다. 안전하지 않은 임시 대상은 422를 반환하며 운영자를 호스트 측 설정 명령으로 안내합니다. dry run은 계속 사용할 수 있으며 파일을 쓰지 않습니다. 지원되는 호스트 측 설정 명령은 [CLI 통합](../guides/CLI-INTEGRATIONS.md)을, 공개 오류 계약은 [오류 정제](./ERROR_SANITIZATION.md)를 참고하십시오.
