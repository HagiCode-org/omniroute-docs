# Изолированные smoke test для CLI

Запустите необязательный harness для уже установленных бинарных файлов Aider, Goose, OpenCode, Qwen Code
или Codex:

```bash
node scripts/cli/smoke-cli-integrations.mjs --targets qwen,codex --json
```

`--bin-dir /absolute/path` добавляет в начало PATH существующий каталог с бинарными файлами. Harness
не устанавливает инструменты. Отсутствующие исполняемые файлы дают `HOLD-missing-binary`; тайм-аут
даёт `HOLD-timeout`. Любой FAIL приводит к завершению процесса с кодом 1; HOLD приводит к
коду 2. Для кода 0 все цели должны получить PASS.

Каждая цель запускается через `omniroute run` против одноразового HTTP-сервера, привязанного к
`127.0.0.1`, с фиксированными несекретными учётными данными sentinel. HOME, каталоги XDG,
домашние каталоги конфигурации CLI и каталог данных OmniRoute временные. Учётные данные провайдеров,
переменные proxy, флаги runtime-загрузчика и существующие конфигурации
не наследуются. Реальные учётные данные upstream не требуются и не принимаются.

Явная опция harness `--inherit-isolated-env` передаёт `--inherit-env` в
`omniroute run`, позволяя флагам подавления метаданных и обновлений, которыми управляет harness, доходить
до стороннего дочернего процесса. По умолчанию она выключена и по-прежнему пересоздаёт внешнее
окружение из того же узкого списка разрешённых переменных: она никогда не наследует секреты вызывающей стороны,
`NODE_OPTIONS`, `NODE_PATH`, `LD_PRELOAD`, `PYTHONPATH` или настройки proxy. Шифрование
хранилища использует несекретный sentinel только внутри одноразового каталога данных.
Harness также выбирает упакованные метаданные моделей LiteLLM и небуферизованный вывод
Python; это фиксированные тестовые настройки, а не значения окружения, передаваемые вызывающей стороной.
Эта опция требует CLI, реализующего `run --inherit-env`; неподдерживаемые launcher
завершаются с обычной ошибкой, и их нельзя засчитывать как успешный smoke.

PASS требует успешного завершения дочернего процесса, ожидаемого пути протокола и модели,
заголовка авторизации с sentinel, завершённого HTTP-ответа и непредсказуемого
сгенерированного сервером маркера ответа в stdout. Маркер не встречается в
prompt, поэтому вывод prompt или диагностического сообщения не может удовлетворить тест. Это доказывает
контракт транспорта и ответа установленного бинарного файла, но не реальную аутентификацию у провайдера,
выполнение инструментов, промышленное развёртывание или все версии CLI.

Runner ограничивает объём перехватываемого вывода и время выполнения. В POSIX он создаёт отдельную
группу процессов и завершает оставшиеся члены этой группы при очистке; в Windows сейчас возвращается
`HOLD-process-isolation`, поскольку эквивалентная очистка потомков не реализована.
Временные файлы и серверные сокеты закрываются после каждой цели. Это изоляция конфигурации
и процессов, **а не сетевая песочница на уровне операционной системы**: сторонние бинарные файлы
могут выполнять собственные запросы метаданных или обновлений. Запускайте только доверенные установленные бинарные файлы
и используйте внешне ограниченное окружение, если требуется полное отсутствие трафика за пределами loopback.

Запустите детерминированные тесты harness без сторонних бинарных файлов:

```bash
node --import tsx/esm --test tests/unit/cli/real-cli-smoke-harness.test.ts tests/unit/cli/real-cli-smoke-safety.test.ts
```

Mock поддерживает OpenAI Chat Completions и Responses API в форматах JSON/SSE. Он никогда не
пересылает запросы провайдеру. Тесты upstream, зависящие от учётных данных, остаются
отдельной opt-in проверкой, и их нельзя выдавать за покрытые этим harness.
