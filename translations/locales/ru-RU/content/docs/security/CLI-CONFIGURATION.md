# Предпросмотр и запись конфигурации CLI

Маршруты `/api/cli-tools/config` и `/api/cli-tools/apply`, требующие аутентификации, возвращают
некэшируемые предпросмотры с маскированием. Они сохраняют существующие проверки аутентификации
и авторизации. Тела запросов отклоняют неизвестные поля. Явный базовый URL
должен использовать HTTP(S) без встроенных имени пользователя и пароля; если он не указан,
используется базовый URL, настроенный на сервере.

Для пакетного предпросмотра `GET /api/cli-tools/config` принимает необязательный параметр запроса `baseUrl`
и берёт учётные данные конфигурации из заголовка
`x-omniroute-config-api-key`. Учётные данные в строке запроса отклоняются.
`POST /api/cli-tools/config` принимает в JSON-теле `toolId`, `baseUrl`, `apiKey` и необязательный
`model`. Ответы используют `Cache-Control: no-store` как при успехе, так и при ошибке.
Текст предпросмотра не является пригодной конфигурацией с учётными данными.

Проекция предпросмотра маскирует сериализованные учётные данные вызывающей стороны и поля учётных данных,
уже присутствующие в объединённых JSONC-, TOML- или YAML-profile. Маршрут apply записывает
исходную конфигурацию; маскирование в предпросмотре не изменяет значения на диске.
Некорректный JSON отклоняется с кодом 400. Публичные ответы об ошибках используют стандартную
санитизированную оболочку ошибки.

Применение конфигурации использует приватный временный файл в каталоге назначения, сбрасывает его на диск
и атомарно переименовывает на место. Файлы и резервные копии используют
режим `0600`; права устанавливаются на принадлежащем дескрипторе до переименования. Символические
ссылки в пути назначения и файлы, не являющиеся обычными, отклоняются. Чтение конфигураций Codex и OpenCode
также отклоняет символические ссылки в конечном пути перед слиянием существующих TOML/JSONC. Это не
означает защиту от противника, контролирующего родительский каталог.

Защита записи в контейнере остаётся активной: небезопасное эфемерное место назначения возвращает
422 и направляет оператора к команде настройки на стороне хоста. Пробный запуск (dry run) по-прежнему
доступен и не записывает файлы. Поддерживаемые команды настройки на стороне хоста см. в разделе [интеграции CLI](../guides/CLI-INTEGRATIONS.md),
а публичный контракт ошибок — в разделе [санитизация ошибок](./ERROR_SANITIZATION.md).
