# Детерминированные стратегии маршрутизации

Self-hosted точка входа gateway в OmniRoute (`/v1/chat/completions`, RIC-738) по умолчанию маршрутизирует запросы
к одному провайдеру. Когда вы настраиваете блок `strategy:`, решение о маршруте
становится **детерминированной, объяснимой политикой** — отличительной особенностью OmniRoute по сравнению с
маршрутизацией «predict» у NotDiamond/Martian, работающей как чёрный ящик.

Каждое решение:

- **Детерминированное** — одна и та же конфигурация и одно и то же состояние среды выполнения дают одного и того же провайдера.
- **Выражено в конфигурации** — одно правило на строку; никакого "一体化智能体", никакой обученной модели.
- **Объяснимое** — каждый ответ содержит `x-omniroute-route-decision`, однострочный
  ответ на вопрос «почему эта модель?» (и «почему НЕ та»).

Это M2 из дифференциации RIC-697 (D3 可审计路由). **Предиктивных /
ML-зависимостей нет** — стратегии представляют собой чистые правила над наблюдаемыми сигналами
(последовательные сбои, заявленная стоимость, измеренная задержка).

## Включение

Добавьте блок `strategy:` в тот же YAML-документ, что и `providers:`, или укажите
в `OMNIROUTE_SELF_HOSTED_STRATEGY` (встроенный YAML) / `OMNIROUTE_SELF_HOSTED_STRATEGY_FILE`
(файл) отдельный документ с `strategy:`. Явная стратегия из env объединяется со
встроенным блоком по каждому ключу.

```yaml
# providers.yaml
providers:
  - id: cheap
    kind: openai
    baseUrl: http://127.0.0.1:11434/v1
    model: llama3
    costPer1MInput: 0.2 # USD per 1M input tokens — used by cost-priority
  - id: fast
    kind: openai
    baseUrl: http://127.0.0.1:8080/v1
    model: gpt-4o-mini
    costPer1MInput: 0.6
  - id: premium
    kind: anthropic
    baseUrl: http://127.0.0.1:8081
    model: claude-sonnet
    costPer1MInput: 3.0

strategy:
  blacklist: [] # provider ids never used
  whitelist: [cheap, fast, premium] # when non-empty, ONLY these are used
  costPriority: true # cheapest eligible candidate first
  latencyAware:
    enabled: true # fastest recent-average candidate first
  cooldown:
    consecutiveFailures: 2 # breaker trips after this many in a row
    cooldownMs: 30000 # …and the provider stays excluded this long
  fallbackChain: [cheap, fast, premium] # explicit fallback order
```

## Пять стратегий

| Стратегия        | Конфигурация                                  | Эффект                                                                                                 |
| ---------------- | --------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| Blacklist        | `blacklist: [id, ...]`                        | Перечисленные провайдеры никогда не становятся кандидатами.                                            |
| Whitelist        | `whitelist: [id, ...]`                        | Если список не пуст — кандидатами являются только перечисленные провайдеры.                            |
| Cooldown/breaker | `cooldown: {consecutiveFailures, cooldownMs}` | После N последовательных сбоев провайдер исключается на заданный интервал. Успех сбрасывает счётчик.   |
| Приоритет стоимости | `costPriority: true`                       | Подходящие кандидаты сортируются по `costPer1MInput` по возрастанию (заявленное значение, никогда не выдуманное). |
| С учётом задержки | `latencyAware.enabled: true`                 | Подходящие кандидаты сортируются по недавней средней задержке запроса по возрастанию. Провайдеры без замеров идут последними. |
| Цепочка fallback | `fallbackChain: [id, ...]`                    | Явный порядок основной→резервный. Имеет приоритет над упорядочением по стоимости/задержке.            |

Фильтры (blacklist / whitelist / cooldown) выполняются первыми и удаляют кандидатов. Затем
этап упорядочения сортирует оставшихся: явный `fallbackChain` имеет приоритет; в остальных случаях
применяются `costPriority`, а затем `latencyAware` в этом порядке.

## Закреплённые провайдеры

Заголовок `x-omniroute-provider` и префикс модели `provider/model` — это **явные
закрепления**, а не предпочтения. Если закреплённый провайдер исключён жёстким фильтром (blacklist /
whitelist / активный cooldown), запрос завершается с `400` и причиной закрепления — gateway
никогда молча не перенаправляет клиента, запросившего конкретного провайдера. Если закрепление
проходит фильтры, оно становится первым кандидатом, а остальные кандидаты служат
его цепочкой fallback.

## Fallback при сбое

Упорядоченный список кандидатов является цепочкой fallback. Когда первый провайдер терпит сбой
(сеть недоступна, соединение отклонено, DNS/TLS или любой не-2xx), gateway переходит
к следующему кандидату, и так далее. Каждый сбой записывается в cooldown breaker, а
каждая попытка замеряется по задержке — поэтому неисправный основной провайдер также переходит в cooldown для _последующих_
запросов. Когда все кандидаты терпят сбой, возвращается последняя нормализованная ошибка (в формате OpenAI). Когда
подходящих кандидатов нет вообще, возвращается `503` с полным объяснимым
решением.

## Объяснимость

Каждый ответ, пройденный через движок стратегий, содержит:

```
x-omniroute-route-decision: cheap(cost-priority: cheap #1) -> fast(cost-priority: fast #2); premium excluded: blacklist: premium forbidden
```

Значение — это упорядоченный список кандидатов плюс все причины исключения — журнал аудита
для вопроса «почему эта модель, почему не та».

## Контракт сбоев (без изменений относительно RIC-738)

- Upstream-ответ не 2xx: его тело нормализуется через `parseUpstreamError` + `buildErrorBody`
  в стандартную структуру OpenAI `error` (Hard Rule #12).
- Сбои на сетевом уровне возвращают нормализованный `502`; после исчерпания всей цепочки
  возвращается последняя нормализованная ошибка.
- Заголовки с учётными данными / сессией, отражённые upstream, удаляются из каждого ответа.
- Конфигурация провайдера с некорректным блоком `strategy:` возвращает `500` — неверно настроенная
  политика никогда не превращается молча в no-op.

## Тесты

- `tests/unit/routing-strategies.test.ts` — 25 модульных тестов чистого движка стратегий:
  разбор, blacklist/whitelist, cooldown breaker, приоритет стоимости, учёт задержки, цепочка
  fallback, комбинированный конвейер, объяснимость.
- `tests/unit/self-hosted-entry.test.ts` — инъекция сбоев по реальному HTTP: основной недоступен
  → fallback успешен; недоступны все → последняя ошибка; закреплённый провайдер в blacklist → 400; cooldown
  исключает неисправного провайдера при следующем запросе; нет подходящих → 503 с объяснимым
  решением.
