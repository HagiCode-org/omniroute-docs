# Идентификатор разговора OpenCode

OpenCode и OpenCode Go повторно используют явные идентификаторы разговора между ходами. Резолвер
проверяет `x-opencode-session`, существующие заголовки affinity/сессии, нативные
заголовки сессии/треда CLI, метаданные запроса, а затем поля сессии/треда верхнего уровня. В JSON-закодированном
`metadata.user_id` Claude ищется идентификатор сессии; один лишь непрозрачный
идентификатор учётной записи или пользователя никогда не считается идентификатором разговора.

Значения с управляющими символами, пустые идентификаторы и идентификаторы длиннее 256
символов игнорируются. Разбор JSON-метаданных ограничен. Перед трансляцией
нормализатор заголовков executor сохраняет этот идентификатор только для провайдеров
OpenCode; заголовки OpenCode для других провайдеров он не добавляет.

Существующее каноническое кодирование `ses_` и fallback на отпечаток разговора
остаются без изменений. Если явного идентификатора нет, непрерывность по-прежнему определяют
первое сообщение пользователя и остальные существующие входные данные отпечатка. Это не
новая граница авторизации и не доказательство изоляции содержимого на стороне upstream.

Реализация находится в `open-sse/utils/opencodeSessionIdentity.ts`,
`open-sse/utils/opencodeHeaders.ts` и
`open-sse/handlers/chatCore/executorClientHeaders.ts`. Регрессионные тесты охватывают
нативные идентификаторы, метаданные Claude, приоритет, недопустимые значения и существующее
поведение отпечатка без платных обращений к upstream.
