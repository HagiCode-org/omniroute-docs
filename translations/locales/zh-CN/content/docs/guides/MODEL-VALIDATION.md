# 验证并添加自定义聊天模型

`omniroute models test-add` 会针对你明确选择的某个提供者连接执行可选的验证，只有所有证明都通过后才会注册该自定义模型。这些请求可能产生提供者费用。该命令同时要求 `--allow-inference` 与 `--yes`；普通的手动模型注册仍未经验证，不会执行推理。

```sh
omniroute models test-add example-model --provider openai --connection CONNECTION_ID --allow-inference --yes
```

请使用已配置服务器中的实际连接 ID。本地与远程 CLI 上下文使用同一个管理端点；当此请求失败时，CLI 绝不会回退到本地数据库。提供者凭据保留在服务器端。合成的工具调用证明不会执行任何 shell、浏览器、文件系统工具或其他真实工具。

## HTTP 约定

`POST /api/provider-models/validate-and-add` 始终需要管理认证，即使普通仪表盘路由允许未认证访问。现有的仪表盘会话、限定范围的管理密钥、本地 CLI 令牌与远程访问令牌策略同样适用。包括认证与校验错误在内的所有响应均使用 `Cache-Control: no-store`。

严格的 JSON 请求体接受以下字段：

| 字段                | 是否必填 | 含义                                                         |
| ------------------- | -------- | ------------------------------------------------------------ |
| `provider`          | 是       | 已存储的精确提供者 ID，最多 120 个字符                        |
| `modelId`           | 是       | 精确的上游模型 ID，最多 240 个字符                            |
| `connectionId`      | 是       | 已存储的精确连接 ID，最多 160 个字符                          |
| `allowInference`    | 是       | 必须为布尔值 `true`                                          |
| `modelName`         | 否       | 显示名称，最多 240 个字符                                     |
| `max_input_tokens`  | 否       | 正的安全整数；由调用方提供的元数据，不是实测上限               |
| `max_output_tokens` | 否       | 正的安全整数；由调用方提供的元数据，不是实测上限               |
| `apiFormat`         | 否       | `chat-completions`（默认）或 `responses`                       |

标识符不能包含空白字符或控制字符。额外的请求体属性、自定义 URL、任意提示词、客户端提供的凭据与回执都会被拒绝。请求体上限为 16 KiB；读取请求体有 10 秒的截止时间。

## 证明与持久化

服务器会生成不可预测的值，并依次检查以下三个请求：

1. 生成请求必须原样返回所要求的 nonce（随机数）。
2. 流式响应会以精确的 nonce 调用一次合成的回显函数。其流必须包含预期的终止原因与结束标记，且之后不能再有数据。
3. 续写请求必须原样返回合成的工具结果。

每个阶段有 20 秒的截止时间、128 个 token 的请求输出预算以及 64 KiB 的响应读取上限。整个操作有 90 秒的截止时间。提供者既有的转换、速率限制与安全处理仍在聊天核心中生效。各提供者可能有各自的 token 预算语义；这些限制不是计费估算。可选的提示词压缩、会话压缩（compaction）与压缩预热在这些合成证明中被禁用，因此它们无法在派发围栏之前发出辅助推理请求。

进程内的派发围栏会检查原生执行器身份、精确模型、连接与凭据。未派发的缓存或绕过结果、同级账号回退、模型回退、代理执行器包装、重试或凭据刷新都不能产生成功的回执。观察器会检查每一次物理 HTTP 发送（包括内部重试分支），并在该次发送前验证最终的 Bearer 请求头与 JSON 中的 model 字段。每个证明只允许一次发送。派发前会先检查连接与提供者的资格。提供者代理重路由模式、生效中的独占租约以及不可用的所选连接都会被拒绝，而不会悄悄改选其他目标。普通 `forcedConnectionId` 路由的语义保持不变。

服务器会在派发前比较其内部的连接与配置快照，并在最终的 SQLite 事务内再次比较。配置或凭据变更会使本次尝试失效。事务会插入先前不存在的自定义模型记录并回读；已存在的模型绝不会被覆盖。同一连接上的其他验证操作在该服务器进程中有一个正在进行时，会被拒绝。

HTTP `201` 返回 `schemaVersion: 1`、`model`、`persistenceVerified: true` 与 `validation`。validation 记录包含 UUID 形式的 `id`、`status: "passed"`、精确的 `provider`、`modelId`、`connectionId`、ISO 格式的 `validatedAt`，以及三个标记为 `passed` 的 `stages`。同样的说明性验证记录会与自定义模型一同存储。它不是客户端可兑换的授权令牌：验证与注册是同一个操作。

常见失败包括：`400` 表示输入或同意无效，`401`/`403` 表示管理授权失败，`408` 表示取消或超出截止时间，`409` 表示冲突、连接不可用或配置已变更，`413` 表示输入过大，`422` 表示证明不完整。错误使用经过脱敏的 OmniRoute 错误信封返回；上游响应体与凭据均不会返回。

## 初始支持的派发范围

严格验证目前支持 `openai` 的原生 Base/Default 执行器路径，以及规范的 OpenAI 兼容 chat/responses 节点，要求单个 Bearer 凭据与精确的 JSON `model` 字段。重定向会在第二个目标能够接收请求之前被拒绝。专用执行器子类与其他提供者 ID 会返回 `VALIDATION_EXECUTOR_UNSUPPORTED`(`422`）。会话池、额外密钥轮换、替代认证头、提供者代理与凭据刷新均被拒绝。该限制仅适用于 Test & Add（测试并添加）；普通聊天保留其既有的提供者、刷新、重试与池化行为。

生效中的运行时插件同样会使严格验证不可用（`VALIDATION_PLUGINS_UNSUPPORTED`）。该请求不会跳过已安装的插件策略：它会在运行该插件之前失败。一个私有的异步请求守卫会阻止在证明期间激活的处理程序（包括延迟的响应或流式工作）在验证作用域中执行。普通请求保留其插件行为。插件配置包含在最终的事务快照检查中。

## 并发范围

同一连接在同一时间最多只运行一个验证（对同一连接的第二个并发请求会被拒绝）。该保护是内存中的一个集合（`src/lib/modelValidation/service.ts` 中的 `activeConnections`)，因此它是按进程划分的：它无法在共享同一数据库的多个 OmniRoute 进程或实例之间协调。

## 本功能不能证明的内容

回执描述的是某一时间点一次成功且有界的互操作性检查。它不能保证未来的可用性、原生工具实现、图像支持、推理质量、定价、上下文窗口容量或所有可能的对话。这些值不会被推断或编造。需要凭据刷新、替代执行器路由或不同规范模型 ID 的模型，即使普通的启用回退的聊天可以工作，也可能无法通过严格检查。请显式刷新或重新配置后，酌情重试。

实现层测试使用隔离的临时数据库、真实的聊天核心与原生执行器，并使用伪造的 HTTP 传输层。它们不能证明上游的实时可用性，也不构成授权付费冒烟测试的依据。
