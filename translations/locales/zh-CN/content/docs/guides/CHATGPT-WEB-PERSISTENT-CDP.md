# ChatGPT Web：持久化 CDP 配置档

将 `CHATGPT_WEB_CODEX_USE_CDP_PROFILE=1` 与已配置的 ChatGPT CDP 端点（`CHATGPT_WEB_CODEX_CDP_URL` 或连接自身的 CDP URL）一同设置，即可复用外部托管的浏览器配置档，而不再创建隔离的上下文。该选项默认关闭：未设置（或取值不为 `1`），以及未配置任何 CDP 端点时，适配器会像以前一样继续创建隔离的上下文和标签页。取值为 `1` 时，适配器还会将并发的 ChatGPT 浏览器标签页数量上限设为 1（默认为 5）。

请使用一个专用的浏览器配置档（profile），并由与 OmniRoute 相同的操作系统用户持有。将调试端口绑定到回环地址，将配置档权限保持为私有，以交互方式登录 ChatGPT，并且只保留一个 ChatGPT 页面处于打开状态。浏览器进程及其启动与恢复由运维人员管理，独立于 OmniRoute。切勿通过公共隧道暴露 CDP。

持久化模式下，每个进程只支持一个账户/工作区，且同一时间只允许一个活跃的浏览器轮次。使用已保存的会话前会先验证账户；仅接受绑定账户的轮换会话令牌，并拒绝其他账户/工作区。不同账户需要各自独立的浏览器配置档，并使用相应隔离的运行时。部署时应只为共享浏览器运行单个网关实例。

校验与推理会租用现有页面。成功、失败和取消都会释放所有权，外部浏览器页面保持打开。新的轮次会重置临时会话并清除过期草稿。持久会话刷新读取的是当前的浏览器状态，而不是注入陈旧的 Cookie。

适配器还能识别当前的输入框、模型选择器和助手回复标记。提交前，它会校验所选的模型系列。原生 Codex 消息 ID 必须在路由清理后保留下来，以便适配器验证该轮次的环境与文件系统权限。

带界面的浏览器即使保存了配置档，也不能保证永久登录，也不能保证不会触发安全校验。无头模式的可用性取决于运行环境。如果 ChatGPT 出现安全验证，请以交互方式使用同一个专用浏览器完成恢复。避免反复启动浏览器，也避免自动重试验证的循环。隐藏或最小化浏览器并不能消除其渲染进程的内存开销。

## 验证

运行持久化上下文测试、原生消息来源测试以及现有的推理输入净化测试。对同一账户验证两次，且不创建更多页面。运行两个原生的 `/v1/responses` 轮次并确认输出各不相同；然后使用无害的工具调用测试真实的 Codex 客户端。验证重启后的持久化与取消后的恢复。不要根据直接的适配器冒烟测试推断端到端成功。
