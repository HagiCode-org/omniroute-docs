# CLI 伴侣

CLI 代码仪表盘内置了一个仅复制的伴侣面板，适用于本版 OmniRoute 支持的可执行 CLI 目标。它不会启动进程、不会写入配置、不会测试推理，也不会把凭据发送到剪贴板。

## 服务器检测不等于浏览器检测

检测、运行与配置状态描述的是运行 OmniRoute 服务器的那台机器。如果你从笔记本打开远程仪表盘，服务器上缺少某个 CLI 并不能说明你的笔记本上也没有安装该 CLI。未知和检测失败的状态会保持明确显示，不会被当作“未安装”。面板中不显示原始诊断错误与配置端点。

请把命令复制到你要使用 CLI 的那台机器的终端中。即使服务器检测失败，伴侣面板也不会阻止你按本地说明操作。

## 本地或远程上下文

先检查你的终端中已经配置的上下文：

```sh
omniroute contexts list
omniroute contexts current
```

将伴侣面板的上下文字段留空，即可使用 CLI 的当前活动上下文；也可以填写一个已存在的上下文名称。命名上下文可以指向本地或远程服务器。仪表盘不会读取你终端的上下文存储，不会创建上下文，也不会复制其凭据。例如，若 `office` 已存在：

```sh
omniroute configure claude --context office
omniroute run claude --context office --dry-run
```

`configure` 是交互式命令，会在你执行它的那台机器上写入配置。`run --dry-run` 只显示启动计划而不启动目标，它并不能证明上游推理可用。运行这些命令之前，请先按照现有的 CLI 上下文流程为终端完成认证。

只有可执行清单声明的能力才会提供。如果某个目标需要模型，在你提供真实的模型标识符之前，它的启动命令会保持不可用。上下文与模型字段只接受受限的字符集，并按字面值处理；shell 操作符、空白字符以及以选项前缀开头的写法都会被拒绝。

如果剪贴板访问失败，面板会报告失败，并让命令保持可见，以便你手动选取。复制操作绝不会执行命令。

## 实现边界

服务器端加载器 `src/lib/cli-helper/companionTargets.ts` 会把可执行清单转换为公开描述符。浏览器只接收目标 ID、显示名称与能力标志，不会接收 Node 模块或运行时密钥。命令校验与状态映射位于 `src/shared/utils/cliCompanion.ts`。面板复用仪表盘现有的批量状态请求，不引入任何执行接口，也不增加额外的状态轮询。
