# 团队成本中心与共享预算

OmniRoute 团队成本中心将彼此独立管理的 API 密钥归入同一个计费所有者之下。它们与 API 密钥分组刻意分开：

```text
API Key --< key_group_members >-- Key Groups   # many-to-many model ACL
API Key --1 active billing binding--> Team     # one billing owner at a time
```

每个人、每个智能体或每个应用各保留一个 API 密钥。按密钥的模型访问、吊销、请求限制、令牌限制和审计身份仍然生效。团队新增的是共享归因、报表和可选的共享预算窗口，并不取代这些控制项。

## 成本语义

团队 API 使用不同的字段，而不是把每个看似美元的数值都当作账单金额：

- `estimatedListCostUsd`：按 OmniRoute 模型定价目录估算的令牌用量。这是第一阶段的团队预算指标。
- `actualProviderCostUsd`：可获得时，由提供者上报或开具发票的成本。第一阶段返回 `null`，不以估算值替代。
- `subscriptionQuotaUsed`：可获得时，提供者订阅配额的使用单位数。第一阶段返回 `null`。
- `compressionSavingsUsd`：压缩带来的估算节省额。第一阶段在团队报表中返回 `null`；现有的压缩分析仍为权威数据。

对于基于订阅的提供者，`estimatedListCostUsd` 可用于成本分摊和比较，但不一定是可开票的提供者成本。

报表会估算所有已记录的尝试，包括带有令牌用量的失败尝试，并显示它们的请求数与令牌总数。因此，失败尝试上的未知价格会将报表的 `hasUnpricedUsage` 置为真。共享预算只评估成功的请求：仅因失败尝试而出现的未知价格不会阻止下一个请求。两个数值均使用当前目录价格，价格变动时会随之变化；两者都不是历史账单。

## 不可变的归因

写入终态用量行时，OmniRoute 会按生效的 `UsageEntry.timestamp` 解析该 API 密钥所属的计费团队，并将得到的团队 ID 存入该行。只有调用方省略时间戳时，才会默认使用当前的系统时间；调用方可以自行提供该时间戳，因此它并非独立的持久化时钟。重新分配密钥不会改写已存储的行。运营人员应避免在密钥仍有进行中的请求时转移它：第一阶段不会持久化单独的请求开始归属预留，归因以该生效的用量条目时间戳为准。

在清理原始用量保留数据之前，团队用量会汇总到 `daily_team_usage_summary` 中，保留团队、API 密钥、提供者、模型、服务层级、令牌类别、成功请求计数，以及每次请求中不同令牌形态的计数。缺失的提供者或模型会存入明确的未知分桶，其中的成功用量会在预算中按失败关闭处理。此前保留、但没有令牌形态计数的行无法还原精确的非线性价格：报表会显示标记为未定价的汇总估算值，而成功的旧版分桶会使预算按失败关闭处理。保留期汇总按 UTC 日划分，每天一个分桶。对于切入已汇总日期的任意时间戳范围，第一阶段会排除整个边界分桶，而不是把用量归到所请求范围之外；当令牌形态计数可用时，完整的 UTC 日报表仍然精确。

## 共享预算行为

团队可以定义：

- `maxBudgetUsd`
- `budgetDuration`：`1d`、`7d` 或 `30d`

第一阶段的执行模式明确为 `soft_committed_usage`。在处理请求之前，OmniRoute 会使用 `estimatedListCostUsd` 汇总当前团队窗口内已提交的成功用量，并在达到上限后拒绝新的流量。没有匹配本地目录价格的用量会被报告为未定价，并使已启用的团队预算按失败关闭处理，而不是悄悄按零计入。预算的重置周期从首次启用时开始；之后对金额、周期或元数据的编辑会保留已确定的重置时间点。过期窗口通过比较并交换（compare-and-swap）更新，按完整周期的整数倍向前推进，因此过期的并发写入方无法把周期往回拨。原始行老化之后，只计入完全位于该滚动窗口之内的完整 UTC 日汇总分桶；不完整的边界日出于保守考虑会被省略，因为在不编造精度的前提下，无法拆分日级分桶。

这并非严格不超支的财务账本。并发请求可能在任一请求提交用量之前都通过预检。要实现严格执行，需要一个原子且幂等的请求账本：

```text
reserve(request_id, estimated_cost)
  -> commit(request_id, actual_cost)
  -> release(request_id, unused_reservation)
```

其不变式为：

```text
committed_spend + active_reservations <= team_budget
```

在对外提供此类模式之前，必须覆盖重试、回退、重复回调、流式取消以及最终成本调整等情形。

## 仪表盘

在 `/dashboard/costs/teams` 打开 **Costs → Teams**。拥有 Management Admin 权限的管理员可以创建和编辑团队、配置其可选的软预算、分配或转移 API 密钥，以及归档团队。转移操作会在确认前显示当前所有者与目标所有者；已归档的团队仍可作为只读报表查看。只需要密钥名称和内部标识符，无需密钥本身。

所选团队保存在 `team` URL 参数中。响应式工具栏位于全宽成本内容上方，包含可搜索的团队下拉框和状态筛选器，且不设第二个侧边栏。搜索框位于下拉框内，仅用于筛选其中的选项；只有在明确选择之后，报表才会变化。报表可按完整的 UTC 日期提供 7 天、30 天或全部时间范围。其中的全部尝试目录估算值，与当前滚动预算窗口内的成功用量金额是分开的。

预算卡片显示重置时间、已知支出、上限和剩余额度。如上所述，未知价格或缺少精确令牌形态的旧版汇总仍按保守方式处理。当保留的日分桶与窗口边界重叠时，`GET /api/teams/{id}` 还会返回 `budgetStatus.hasPartialRetainedUsage`。此时页面会突出显示覆盖不完整的情况，并不显示剩余额度的数值；它不会改变现有的软执行策略，也不会从日汇总中推断出时间级别的细节。

对于管理端的选择器，`GET /api/teams?includeKeyOptions=true` 会添加一份包含全部密钥的元数据投影，其字段为 `id`、`name`、`teamId` 和 `teamName`。分配接口接受可选的 `expectedTeamId`（对于未分配的密钥可为 `null`）；如果所有者已变更，接口会在修改任何历史记录之前返回 409。未传该字段的现有客户端保持原有行为。

## 管理 API

所有团队端点都使用 OmniRoute 管理认证。

| 方法                       | 端点                      | 用途                              |
| -------------------------- | ------------------------- | --------------------------------- |
| `GET` / `POST`             | `/api/teams`              | 列出或创建团队                    |
| `GET` / `PATCH` / `DELETE` | `/api/teams/{id}`         | 查看、更新或归档团队              |
| `GET` / `PUT` / `DELETE`   | `/api/teams/{id}/members` | 列出、分配或取消分配 API 密钥     |
| `GET`                      | `/api/teams/{id}/usage`   | 团队汇总及按密钥的下钻明细        |

`DELETE /api/teams/{id}` 会归档团队，而不是物理删除。它会关闭进行中的密钥分配，同时保留用量归因。

## 备份与紧急恢复

SQLite 备份以及包含历史记录的 JSON 导出会包含保留的团队汇总。数据库紧急关键状态抢救属于尽力而为的配置恢复，而不是完整的用量备份：它可以保留团队和绑定关系，但不会恢复保留的用量。走完该恢复路径之后，在依赖历史报表或预算总额之前，应先恢复完整备份。

## 第一阶段的有意限制

第一阶段不新增 Organization、User、Role、Membership、委派的团队管理员、SSO 或 SCIM 对象。现有的全局 Management Admin 负责管理团队配置。它也不会将 Quota Share 当作严格的美元账本复用：Quota Share 仍适用于提供者容量与公平性分配，而在预留记账机制出现之前，团队财务执行将明确保持为软执行。
