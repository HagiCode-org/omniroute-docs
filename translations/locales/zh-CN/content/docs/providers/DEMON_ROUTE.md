# Demon Route（API 密钥网关）

Demon Route 提供兼容 OpenAI 的**外部托管**模型网关。其目录包含开源权重模型和独立微调的模型；没有 OpenAI、Anthropic、Google 的闭源模型 SKU。当前的模型 ID、费用、权益与隐私政策，请参阅[官方 API 文档](https://demonroute.com/docs)、[模型目录](https://demonroute.com/models)和[定价页](https://demonroute.com/pricing)。

## 配置连接

1. 在 [demonroute.com](https://demonroute.com) 创建 Demon Route 账户和 API 密钥。付费模型**以及**其有条件赠送通道，都需要先完成一笔已确认的充值。OmniRoute 刻意不把该提供者标记为 `hasFree`：赠送通道**并非无条件**开放。
2. 在 **提供者 → API 密钥提供者 → Demon Route** 中新建连接并粘贴密钥。内置端点为 `https://api.demonroute.com/v1`；**不要**将 `/chat/completions` 后缀作为 OpenAI 兼容节点 URL 填入。
3. 在连接的 **可用模型** 中，选择 **从 /models 导入**或启用 **自动同步**，以获取你的密钥可访问的模型。内置的少量种子列表仅用于离线回退，**不能**证明当前权限、模型健康状况或价格。
4. 选择一个精确且区分大小写的上游渠道 ID，并保留其供应商前缀（例如 `dphn/Dolphin3.0-Llama3.1-8B`）。在 OmniRoute API 上，需要在前面**仅加一次** `demonroute/` 前缀，得到 `demonroute/dphn/Dolphin3.0-Llama3.1-8B`。多出的斜杠是有意为之：上游的供应商/模型字符串不得被截断或改写。
5. 在通过仪表盘将其加入回退组合之前，先分别测试非流式和流式对话。工具支持、上下文长度、模态和定价**因模型而异**；不要假定每个模型都支持工具或视觉能力。

## 请求示例

使用独立的 **OmniRoute 网关** API 密钥时，本地非流式冒烟请求如下：

```bash
curl -sS http://localhost:20128/v1/chat/completions \
  -H "Authorization: Bearer ${OMNIROUTE_API_KEY}" \
  -H "Content-Type: application/json" \
  -d '{"model":"demonroute/dphn/Dolphin3.0-Llama3.1-8B","stream":false,"messages":[{"role":"user","content":"Say hello."}]}'
```

将同一端点与 `"stream":true` 及 `curl -N` 配合使用，即可验证 SSE。上面的密钥用于向 **OmniRoute 验证客户端身份**。Demon Route 自身的 Bearer 密钥只应保存在其已存储的提供者连接中；**切勿将提供者密钥粘贴到源代码、组合定义、日志或截图中**。冒烟请求是真实的上游请求，可能会消耗余额或每日配额。

## 端点支持与运行边界

| 接口面                           | 行为                                                                                                                                    |
| -------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------- |
| Chat Completions                 | `/v1/chat/completions`，支持 JSON 与 SSE 流式输出                                                                                       |
| 模型发现                         | `/v1/models`，**需要**已连接的 Bearer 密钥；导入每个密钥的实时模型列表                                                                  |
| 嵌入                             | 未声明：未验证任何支持嵌入的模型用于此网关，因此不将其列为嵌入提供者                                                                    |
| Responses、图像、语音、视频      | 本集成未宣传：不因其与 OpenAI 相似而推断任何提供者支持                                                                                  |
| 时限                             | 内置配置中为 120 秒的请求与首字节上限；上游建议客户端至少允许 120 秒                                                                    |
| 余额 / 配额                      | 预付费网关；`402` 表示余额不足，`429` 表示按密钥限流，`401` 表示认证问题                                                               |

Demon Route 目前描述了一条有条件的赠送额度通道：完成已确认的充值后，每天最多 50 次请求，并声称失败请求会被退款。这些都是**提供者政策**，并非 OmniRoute 实现或验证过的功能。在启用自动回退之前，请查看官方定价：OmniRoute 不保证退款或零成本。`429` 可能是暂时性的；`402` 需要补充余额，而不是立即反复重试。其自身文档宣称，已退役的 ID 会提前 30 天通知，并提供 90 天的后继政策，但本地种子列表并不保证旧 ID 仍可用。关于第三方上游主机的隐私声明，同样由 Demon Route 及其主机管辖。

如果模型导入失败，请先检查密钥及其按密钥的模型权限；不要把离线种子回退当作实时同步成功。若旧模型的对话返回 `404`，请重新导入目录，并选择当前的上游渠道名称。若流式输出停滞，请检查客户端超时和账户限制，同时不要禁用 OmniRoute 正常的出站 URL、代理或凭据保护措施。

## 验收与故障排查清单

- **测试前：**确认连接已启用，其 Bearer 密钥属于预期的 Demon Route 账户，且所选模型出现在该账户的实时目录中。静态种子不能证明具备访问权限。
- **发现：**使用 **从 /models 导入**，然后检查导入的标识符，不得改变其大小写或 `vendor/model` 中的斜杠。若实时请求失败，请区分回退种子与成功的同步。
- **对话：**先发出一个简短的非流式请求，然后验证流式输出能返回有效的 SSE 事件并正常结束。客户端超时可能需要超过内置的 120 秒上游超时。
- **路由：**在将模型加入组合之前，先检查一次直接的模型调用。然后验证回退行为，并确认客户端可见的错误、追踪和日志不会泄露已存储的提供者密钥。
- **错误：**`401` 时重新检查密钥，`402` 时检查预付费余额，`429` 时遵守提供者的速率限制，`404` 时重新导入实时模型列表。避免立即进行无限制的重试。
- **费用：**成功的实时对话测试可能产生计费。本 PR 中的离线测试未确立任何关于实时账户权限、上游退款、配额或定价的断言。

如需了解更广泛的提供者与组合工作流，请参阅[用户指南](../guides/USER_GUIDE.md)。
