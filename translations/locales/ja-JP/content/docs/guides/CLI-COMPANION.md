# CLI Companion

CLI Code の dashboard には、この OmniRoute バージョンがサポートする実行可能な CLI ターゲット向けの
コピー専用 Companion が含まれています。プロセスの起動、設定の書き込み、推論のテスト、
認証情報の clipboard への送信は行いません。

## サーバー側の検出はブラウザー側の検出ではない

検出、ランタイム、設定の各ステータスは、OmniRoute サーバーを実行しているマシンの状態を表します。
手元のノート PC からリモートの dashboard を開いた場合、そのサーバー上に CLI が見つからなくても、
ノート PC にインストールされている CLI については何も言えません。不明および検出失敗の状態は
明示的なまま保たれ、「未インストール」としては扱われません。生の診断エラーや設定 endpoint は、
このパネルには表示されません。

CLI を使いたいマシンのターミナルにコマンドをコピーしてください。
サーバー側の検出が失敗しても、Companion はローカル向けの手順をブロックしません。

## ローカルまたはリモートのコンテキスト

まず、ターミナルにすでに設定されているコンテキストを確認します。

```sh
omniroute contexts list
omniroute contexts current
```

Companion のコンテキスト欄を空のままにすると CLI のアクティブなコンテキストが使われます。
または、既存のコンテキスト名を入力します。名前付きコンテキストは、ローカルまたはリモートの
サーバーを指すことができます。dashboard は、ターミナルのコンテキストストアの読み取り、
コンテキストの作成、認証情報のコピーを行いません。たとえば `office` がすでに存在する場合：

```sh
omniroute configure claude --context office
omniroute run claude --context office --dry-run
```

`configure` は対話式で、実行したマシン上に設定を書き込みます。`run --dry-run` は、
ターゲットを起動せずに起動プランを表示します。upstream の推論が動作することを確認するものではありません。
これらのコマンドを実行する前に、既存の CLI コンテキストのワークフローでターミナルを認証してください。

実行可能な manifest で宣言された機能のみが提供されます。ターゲットがモデルを必要とする場合、
実際のモデル識別子を指定するまで、その起動コマンドは利用できないままです。
コンテキスト/モデルの欄は限定されたリテラル文字セットのみを受け付け、
シェル演算子、空白、先頭のオプション構文は拒否されます。

clipboard へのアクセスに失敗した場合、パネルはその失敗を報告し、手動で選択できるように
コマンドを表示したままにします。コピーがコマンドを実行することはありません。

## 実装上の境界

`src/lib/cli-helper/companionTargets.ts` のサーバー専用ローダーは、実行可能な manifest を
公開ディスクリプターに射影します。ブラウザーが受け取るのはターゲット ID、表示名、機能フラグのみで、
Node モジュールやランタイムのシークレットは受け取りません。
コマンドの検証とステータスのマッピングは `src/shared/utils/cliCompanion.ts` にあります。
パネルは dashboard の既存のバッチステータスリクエストを再利用し、
実行 API や追加のステータスポーリングは導入しません。
