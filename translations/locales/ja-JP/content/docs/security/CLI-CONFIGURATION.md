# CLI設定のプレビューと書き込み

認証済みの`/api/cli-tools/config`および`/api/cli-tools/apply`ルートは、キャッシュ不可で、
機密情報を伏せたプレビューを返します。既存の認証・認可のチェックは維持されます。
リクエストボディは未知のフィールドを拒否します。明示的なベースURLは、ユーザー名/パスワードの認証情報を
埋め込まないHTTP(S) を使用する必要があります。省略された場合は、サーバーに設定されたベースURLが使用されます。

バッチプレビューでは、`GET /api/cli-tools/config`は任意の`baseUrl`クエリパラメーターを受け付け、
設定用の認証情報を`x-omniroute-config-api-key`ヘッダーから取得します。クエリ文字列内の認証情報は拒否されます。
`POST /api/cli-tools/config`は、JSONボディで`toolId`、`baseUrl`、`apiKey`、および任意の`model`を受け付けます。
レスポンスは、成功パスとエラーパスの両方で`Cache-Control: no-store`を使用します。
プレビューのテキストは、認証情報を含む使用可能な設定ではありません。

プレビューの射影は、シリアライズされた呼び出し元の認証情報と、マージされたJSONC、TOML、またはYAMLのprofileに
すでに存在する認証情報フィールドを伏せます。applyルートは元の設定を書き込みます。
プレビューでの伏せ字処理がディスク上の値を変更することはありません。
不正な形式のJSONは400で拒否されます。公開エラーレスポンスは、標準のサニタイズ済みエラーエンベロープを使用します。

設定の適用では、宛先ディレクトリー内の非公開の一時ファイルを使用し、フラッシュしたうえで、
アトミックにリネームして所定の位置に配置します。ファイルとバックアップはモード`0600`を使用し、
パーミッションはリネームの前に、所有しているディスクリプターに設定されます。
最終的な宛先がシンボリックリンクである場合や、通常ファイルでない場合は拒否されます。
CodexとOpenCodeの読み取りも、既存のTOML/JSONCをマージする前に、最終パスのシンボリックリンクを拒否します。
これは、親ディレクトリーを制御する攻撃者に対する保護を主張するものではありません。

コンテナーの書き込みガードは引き続き有効です。安全でない一時的な宛先は422を返し、
オペレーターにホスト側のセットアップコマンドを案内します。ドライランは引き続き利用可能で、ファイルを書き込みません。
サポートされるホスト側のセットアップコマンドについては[CLI連携](../guides/CLI-INTEGRATIONS.md)を、
公開エラーの契約については[エラーのサニタイズ](./ERROR_SANITIZATION.md)を参照してください。
